## 개발 방향

MORT 수준의 완성도를 목표로 하되, **현재 구현 가능한 범위 안에서 최대한** 만드는 것을 원칙으로 한다.

핵심 가치는 그대로 유지한다:
- OCR 오류를 LLM이 교정해서 번역
- 문맥(이전 번역 히스토리)을 참고해서 자연스러운 번역
- **번역 프로필**: 해당 콘텐츠의 장르/분위기/인물 정보를 미리 주입해서 맥락에 맞는 번역

---

## 현재 동작 가능한 것

- 영역 지정 → Gemini(AI Studio/Vertex) → 오버레이 번역 표시
- Vision 모드 (설정 → 번역 탭에서 체크박스 활성화)
- 글로벌 단축키, 변경 감지, 번역 캐시, 문맥 기억
- 번역 로그 파일 저장, 진단 정보 복사

## Phase 1 — 안정화 (짧고 확실한 것)

### 1-1. OCR 신뢰도 필터링

**무엇인가**  
Tesseract는 모든 인식 결과에 신뢰도 점수(0~100)를 붙인다. 배경 패턴이나 아이콘처럼 텍스트가 아닌 것을 억지로 읽으면 conf=8~15처럼 낮게 나온다. 이런 줄을 번역에 보내면 API 비용만 쓰고 엉뚱한 결과가 나온다.

**구현 방법**  
`pipeline.py`에서 `extract_lines()` 결과를 번역에 넘기기 전에 1줄 필터 추가:
```python
line_boxes = [lb for lb in line_boxes if lb.confidence >= 30.0]
```

**노력**: 매우 낮음 (5분)  
**충돌 위험**: 거의 없음. 기존 흐름에서 줄을 걸러내기만 함  
**주의점**: 임계값 30이 너무 높으면 실제 텍스트도 날아갈 수 있음. 로그에서 `conf=` 수치 보면서 조정 가능

---

### 1-2. API 키 암호화

**무엇인가**  
현재 API 키가 `config.json`에 평문으로 저장됨. 다른 사람이 파일을 열면 키가 그대로 노출됨.

**구현 방법**  
`cryptography` 라이브러리의 Fernet 대칭 암호화 사용. 암호화 키는 이 PC에서만 생성되는 값(머신 고유 ID 등)으로 유도해서 `%APPDATA%` 등 별도 경로에 보관.

**노력**: 중간 (1~1.5시간)  
**충돌 위험**: 중간
- 기존에 평문으로 저장된 키를 처음 실행 시 자동 암호화하는 마이그레이션 필요
- 암호화 키 파일을 분실하면 API 키 복구 불가 → 재입력 안내 필요  

**주의점**: 완전한 보안보다 "파일을 열어도 바로 안 보이는" 수준으로 구현. 과도한 설계 지양

## Phase 2 — 핵심 기능

### 2-1. 번역 프로필

**무엇인가**  
번역 전에 해당 콘텐츠의 배경 정보를 LLM에게 미리 알려주는 기능. 단순 키워드 몇 개만 넣어도 번역 톤과 용어가 크게 달라진다.

예시:
- 게임: `레지던트 이블 시리즈 / 에이다 웡 / 여성 / 첩보 스릴러`
- 논문: `의학 논문 / 대장암 / 전문 용어 원문 병기`
- 애니메이션: `이세계 판타지 / 주인공 남성 10대 / 경어체`

**사용 흐름**
```
처음 1회: 키워드 입력 → [자동 생성] → Gemini가 프로필 채움 → 확인/수정 → [저장]
이후:    설정 → 프로필 드롭다운에서 선택 → 끝 (profiles.json에서 불러옴)
번역 시: 선택된 프로필이 시스템 프롬프트에 자동 반영
```

**구현 상세**

데이터 구조 (`core/profiles.py`):
```python
@dataclass
class TranslationProfile:
    name: str              # "레지던트 이블 2"
    genre: str             # "서바이벌 호러, 3인칭 액션"
    tone: str              # "긴박한, 어두운, 공포"
    glossary: dict[str,str] # {"Ada Wong": "에이다 웡", "R.P.D.": "라쿤시 경찰서"}
    extra_instruction: str  # "캐릭터 대사는 반말, 시스템 메시지는 경어체"
```

저장: `profiles.json`에 프로필 리스트를 저장. 여러 개 만들어두고 콘텐츠에 따라 선택.

자동 생성: 사용자가 키워드 입력 + [자동 생성] 클릭 시, 기존 Gemini provider에 별도 API 호출 (번역 흐름과 완전 분리). Gemini가 JSON 형식으로 프로필 생성 → 파싱해서 UI 필드에 채움 → 사용자가 확인/수정 후 저장.

번역 반영: `translator.py`의 `system_hint`에 프로필 텍스트 블록 추가:
```
【번역 맥락 정보】
- 콘텐츠: 레지던트 이블 2
- 장르: 서바이벌 호러
- 분위기: 긴박한, 어두운
- 용어집: Ada Wong→에이다 웡, R.P.D.→라쿤시 경찰서
- 추가 지시: 캐릭터 대사는 반말
```

건드리는 파일:
- `core/profiles.py` (신규) — 데이터 구조 + 저장/불러오기 + LLM 자동 생성
- `ui/settings.py` — "번역 프로필" 탭 추가
- `core/translator.py` — `system_hint`에 프로필 텍스트 주입
- `main.py` — 프로필 매니저를 translator에 연결
- `infra/config.py` — 활성 프로필 이름 저장

**노력**: 중간 (1.5~2시간)  
**충돌 위험**: 매우 낮음
- `system_hint` 파라미터에 텍스트를 이어붙이는 것이라 기존 번역 흐름을 건드리지 않음
- 프로필이 너무 길면 토큰 소비 증가. 500자 이내 권장으로 UI에서 안내
- 프로필 없이도 기존과 동일하게 동작  
- 자동 생성 실패 시 빈 필드를 보여주고 사용자가 수동 입력 가능

### 2-2. 사이드 패널

**무엇인가**  
오버레이 대신 화면 오른쪽(또는 원하는 위치)에 별도 창을 띄워서 번역 히스토리를 표시하는 방식. 전체 화면 게임이나 오버레이가 방해될 때 대안이 됨.

**구현 방법**  
- `display/panel.py`에 스크롤 가능한 QWidget 구현
- 번역 결과가 올 때마다 맨 위에 추가 (히스토리 형태)
- 트레이 메뉴에서 "오버레이 ↔ 패널" 전환

**노력**: 높음 (2~3시간)  
**충돌 위험**: 중간
- 오버레이와 패널이 동시에 활성화되지 않도록 상태 관리 필요
- 멀티 모니터 환경에서 패널 위치 지정이 복잡할 수 있음
- 전환 시 오버레이 숨김/패널 표시, 역방향 전환 시 정리가 필요  

**주의점**: 먼저 오버레이 모드를 완전히 안정화한 뒤 진행하는 게 좋음
