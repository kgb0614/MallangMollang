# 말랑몰랑 (MallangMollang) — Product Requirements Document

**문서 버전:** v1.1
**작성일:** 2026-06-01 (최종 수정: 2026-06-11)
**상태:** 구현 중 (Phase 1 MVP 거의 완료)

## 1. 개요 (Overview)

**말랑몰랑**은 Windows PC 환경에서 동작하는 AI 하이브리드 화면 번역 유틸리티이다.

기존 화면 번역 도구(MORT 등)는 로컬 OCR이 추출한 텍스트를 그대로 번역 API에 전달하는 구조로, OCR 오인식이 번역 품질을 직접적으로 훼손하는 "Garbage In, Garbage Out" 문제를 안고 있다. 말랑몰랑은 이 파이프라인 사이에 LLM(대규모 언어 모델)을 배치하여, OCR 오류를 문맥 기반으로 교정한 뒤 자연스러운 번역을 제공하는 것을 핵심 가치로 한다.

---

## 2. 배경 및 문제 정의 (Background & Problem Statement)

### 2.1 기존 도구의 한계

현재 시장에는 MORT, WindowTranslator, RSTGameTranslation 등의 화면 번역 도구가 존재한다. 이들은 공통적으로 다음과 같은 문제를 가진다.

**OCR 인식률 문제 (Garbage In, Garbage Out)**
화려한 배경, 특이한 폰트, 낮은 해상도 등으로 인해 로컬 OCR이 글자를 잘못 읽으면(예: `l`→`I`, `rn`→`m`), 번역 결과가 완전히 망가진다. 기존 도구는 OCR 결과를 검증 없이 번역 엔진에 전달하기 때문에 이 문제를 구조적으로 해결할 수 없다.

**문맥 없는 직역 (Context Ignorance)**
화면에 현재 표시된 한 줄만 번역하므로, 앞뒤 대화 흐름을 파악하지 못한다. 동음이의어 오역, 어색한 대명사 처리, 스토리 맥락과 동떨어진 번역이 빈번하게 발생한다.

**불필요한 API 호출과 화면 깜빡임**
화면 내용이 바뀌지 않았는데도 주기적으로 번역 API를 호출하여 비용을 낭비하고, 번역 결과가 반복적으로 갱신되면서 화면이 깜빡거린다.

**웹/문서 환경 비친화적**
대부분의 도구가 게임 대화창처럼 고정된 작은 영역에 최적화되어 있어, 텍스트 양이 많고 레이아웃이 다양한 웹 페이지나 문서 환경에서는 사용성이 크게 떨어진다.

### 2.2 말랑몰랑이 해결하는 것

말랑몰랑은 "로컬 OCR + LLM"의 하이브리드 구조를 통해, OCR이 불완전한 텍스트를 뱉어도 LLM이 문맥 기반으로 교정하고 자연스럽게 번역하는 파이프라인을 제공한다. 변경 감지와 캐시 시스템으로 불필요한 API 호출을 억제하고, 두 가지 조작 모드(영역 지정 / 커서 추적)를 통해 게임과 웹/문서 환경 모두에 대응한다.

## 3. 목표 및 비목표 (Goals & Non-Goals)

### 3.1 목표

- **G1.** OCR 오인식을 LLM으로 교정하여, 기존 도구 대비 체감 번역 정확도를 향상시킨다.
- **G2.** 이전 번역 맥락을 기억하여 문맥이 이어지는 자연스러운 번역을 제공한다.
- **G3.** 변경 감지 및 캐시 시스템을 통해 불필요한 API 호출을 최소화한다.
- **G4.** 영역 지정 모드와 커서 추적 모드를 지원하여 게임 및 웹/문서 환경 모두에 대응한다.
- **G5.** 클라우드 API(BYOK)와 로컬 모델(Ollama)을 모두 지원하여 사용자 선택권을 보장한다.

### 3.2 비목표 (1차 스코프에서 제외)

- **NG1.** macOS, Linux, 모바일 환경 지원 — Windows 전용으로 한정한다.
- **NG2.** 자동 폰트/색상 매칭 — 오버레이는 사용자 커스텀 프리셋 방식으로 처리한다.
- **NG3.** 음성 번역, TTS — 텍스트 번역에 집중한다.
- **NG4.** 자체 번역 서버 운영 — BYOK 또는 로컬 모델 방식으로 서버 비용을 Zero로 유지한다.
- **NG5.** 게임 후킹을 통한 텍스트 직접 추출 — OCR 기반 캡처만 1차 스코프에 포함한다.

## 4. 타겟 사용자 (Target Users)

### 4.1 주 사용자 (Primary)

**한국어 사용자로서 외국어 콘텐츠를 소비하는 PC 유저**

- 번역이 지원되지 않는 해외 게임(특히 인디 게임)을 플레이하는 유저
- 외국어 웹 페이지, 기술 문서, 아티클 등을 탐색하는 유저

### 4.2 사용 환경 특성

- Windows PC (듀얼 모니터 환경 포함)
- 전체 화면 게임과 다중 프로세스를 동시에 운용
- 영어, 일본어, 중국어 콘텐츠가 주 번역 대상

## 5. 사용자 시나리오 (User Scenarios)

### 시나리오 1: 외국어 게임 플레이 (영역 지정 모드)

사용자가 영어로 된 인디 게임을 전체 화면으로 실행하고 있다. 게임 내 대화창의 위치가 고정적이므로, 말랑몰랑에서 해당 영역을 드래그하여 지정한다. 이후 대화가 진행될 때마다 말랑몰랑이 해당 영역을 자동으로 캡처하고, OCR → LLM 번역 파이프라인을 거쳐 오버레이로 번역 결과를 표시한다. 대화가 바뀌지 않으면 번역이 갱신되지 않아 깜빡임이 없고, 새 대사가 나오면 이전 맥락을 참고하여 자연스러운 번역이 표시된다.

### 시나리오 2: 외국어 웹 페이지 탐색 (커서 추적 모드)

사용자가 일본어 기술 블로그를 읽고 있다. 커서 추적 모드를 활성화하면, 마우스 커서가 위치한 텍스트 주변을 자동으로 캡처하여 번역하고 툴팁 형태로 표시한다. 브라우저 내장 번역과 달리 페이지 레이아웃을 건드리지 않으며, 원하는 부분만 선택적으로 번역할 수 있다.

### 시나리오 3: 번역 스타일 커스터마이징

사용자가 배경이 어두운 게임을 플레이 중이라 기본 오버레이 글꼴 색이 잘 보이지 않는다. 설정에서 오버레이 프리셋을 수정하여 흰색 폰트 + 반투명 검정 배경으로 변경하고, 이를 "다크게임용"이라는 이름으로 프리셋 저장한다. 다른 게임에서도 같은 프리셋을 불러와 바로 적용할 수 있다.

## 6. 기능 요구사항 (Functional Requirements)

### F1. 화면 캡처 (Screen Capture)

| 항목 | 내용 |
|------|------|
| **F1-1. 영역 지정 캡처** | 사용자가 화면 위에서 직사각형 영역을 드래그하여 지정한다. 지정된 영역은 설정된 주기(기본 1초)마다 자동으로 캡처된다. 복수 영역 지정을 지원한다. |
| **F1-2. 커서 추적 캡처** | 마우스 커서 위치를 기준으로 주변 텍스트 영역을 자동 감지하여 캡처한다. 캡처 범위는 설정에서 조절 가능하다. |
| **F1-3. 모드 전환** | 단축키를 통해 영역 지정 모드 ↔ 커서 추적 모드를 즉시 전환할 수 있다. |
| **F1-4. 듀얼 모니터 지원** | 모니터를 지정하여 캡처 대상을 특정 화면으로 한정할 수 있다. |

### F2. 변경 감지 (Change Detection)

| 항목 | 내용 |
|------|------|
| **F2-1. 이미지 해시 비교** | 이전 캡처 이미지와 현재 캡처 이미지의 해시값을 비교하여, 유의미한 변화가 없으면 이후 파이프라인(OCR, 번역)을 건너뛴다. |
| **F2-2. 민감도 설정** | 변경 감지 임계값을 사용자가 조절할 수 있다. 임계값이 높으면 작은 변화도 감지하고, 낮으면 큰 변화만 감지한다. |

### F3. OCR 엔진 (OCR Engine)

| 항목 | 내용 |
|------|------|
| **F3-1. Tesseract 연동** | 기본 OCR 엔진으로 Tesseract를 사용한다. |
| **F3-2. 다국어 인식** | 영어, 일본어, 중국어(간체/번체) 인식을 지원한다. 사용자가 인식 대상 언어를 설정에서 선택할 수 있다. |
| **F3-3. 이미지 전처리** | OCR 정확도를 높이기 위해 캡처 이미지에 대해 이진화, 노이즈 제거, 대비 보정 등의 전처리를 수행한다. |

### F4. 번역 캐시 (Translation Cache)

| 항목 | 내용 |
|------|------|
| **F4-1. 텍스트 해시 캐시** | OCR로 추출된 텍스트의 해시값을 키로, 번역 결과를 값으로 저장한다. 동일 텍스트가 재등장하면 캐시된 번역을 즉시 반환한다. |
| **F4-2. 캐시 크기 관리** | 캐시 최대 크기를 설정할 수 있으며, 초과 시 LRU(Least Recently Used) 방식으로 오래된 항목을 제거한다. |
| **F4-3. 캐시 수동 초기화** | 사용자가 캐시를 수동으로 비울 수 있다. |

### F5. LLM 번역 엔진 (LLM Translation Engine)

| 항목 | 내용 |
|------|------|
| **F5-1. OCR 오류 교정** | OCR이 추출한 원문 텍스트를 LLM에 전달할 때, 문맥상 명백한 오타 및 오인식을 교정한 뒤 번역하도록 프롬프트를 구성한다. |
| **F5-2. 문맥 기억** | 직전 3~5회의 번역 결과를 프롬프트에 포함하여, 대화 흐름이 이어지는 자연스러운 번역을 유도한다. 문맥 기억 길이는 설정에서 조절할 수 있다. |
| **F5-3. 번역 방향 설정** | 원문 언어와 번역 대상 언어를 설정에서 지정할 수 있다. 기본값은 "자동 감지 → 한국어"이다. |
| **F5-4. 사용자 프롬프트 커스터마이징** | 번역 톤, 문체, 용어 등을 사용자가 커스텀 프롬프트를 통해 조정할 수 있다. (예: "반말로 번역해줘", "전문 용어는 원문 병기") |
| **F5-5. Vision API 모드** | Vision을 지원하는 LLM(Gemini, GPT-4o 등)을 사용하는 경우, 캡처 이미지를 LLM에 직접 전달하여 텍스트 인식과 번역을 한 번에 처리할 수 있다. 이 경우 OCR 단계(F3)를 건너뛴다. 사용자가 설정에서 "OCR + 텍스트 번역" 또는 "Vision 직접 번역" 중 선택한다. |
| **F5-6. 번역 프로필 (Translation Profile)** | 번역 대상 콘텐츠의 성격을 사전에 정의하여 번역 품질을 높이는 기능. 스타일 프리셋이 시각적 설정(폰트, 색상)을 관리한다면, 번역 프로필은 번역 성격(톤, 용어, 문맥)을 관리한다. |
| **F5-6a. 수동 프로필 설정** | 사용자가 콘텐츠 이름, 장르/카테고리, 분위기(어조), 고유 용어집(용어-번역 쌍), 추가 지시를 입력하면, 이를 기반으로 시스템 프롬프트를 자동 조립한다. 프로필은 `profiles.json`에 저장하여 다음 사용 시 불러올 수 있다. |
| **F5-6b. LLM 자동 생성** | 키워드(콘텐츠 이름 등)를 입력하면 LLM에 별도 API 호출(번역 흐름과 분리)을 통해 장르, 분위기, 용어집 등을 자동 생성한다. 사용자는 자동 생성된 프로필을 확인하고 수정한 뒤 저장할 수 있다. |
| **F5-6c. Steam 메타데이터 자동 연동 (Phase 3)** | 게임 이름을 입력하면 Steam API에서 장르, 태그, 설명문을 자동으로 가져와 번역 프로필을 생성한다. |
| **F5-6d. 콘텐츠 카테고리 퀵 선택 (Phase 3)** | 웹/문서 번역 시 "기술 문서", "뉴스 기사", "캐주얼 블로그", "학술 논문" 등의 카테고리를 선택하여 톤에 맞는 번역을 유도한다. |

### F6. LLM 프로바이더 관리 (LLM Provider Management)

| 항목 | 내용 |
|------|------|
| **F6-1. 클라우드 API 연동 (BYOK)** | 사용자가 본인의 API 키를 입력하여 외부 LLM 서비스를 이용한다. 지원 프로바이더: OpenAI, Google Gemini, Anthropic Claude. |
| **F6-2. 로컬 모델 연동** | Ollama 또는 LM Studio를 통해 로컬에서 구동되는 오픈소스 모델과 연동한다. Ollama의 로컬 API 엔드포인트(기본 `http://localhost:11434`)에 접속하는 방식이다. |
| **F6-3. 프로바이더 전환** | 설정에서 사용할 프로바이더와 모델을 선택할 수 있으며, 런타임 중 전환이 가능하다. |
| **F6-4. API 키 안전 저장** | API 키는 로컬에 암호화하여 저장하며, 평문으로 노출되지 않는다. |

### F7. 번역 표시 (Display)

| 항목 | 내용 |
|------|------|
| **F7-1. 오버레이 모드** | 번역 결과를 원문 위에 반투명 자막 형태로 덮어씌운다. 항상 최상위(Always on Top)로 표시되며, 마우스 클릭이 오버레이를 투과(Click-through)하여 하위 창에 전달된다. |
| **F7-2. 사이드 패널 모드** | 번역 결과를 화면 한쪽에 독립 패널로 표시한다. 패널 위치(좌/우/상/하)와 크기를 조절할 수 있다. |
| **F7-3. 표시 모드 전환** | 단축키를 통해 오버레이 ↔ 사이드 패널을 즉시 전환할 수 있다. |
| **F7-4. 스타일 프리셋** | 폰트 종류, 크기, 색상, 배경 색상, 배경 투명도, 외곽선 유무를 설정하고 프리셋으로 저장/불러오기 할 수 있다. |

### F8. 설정 및 단축키 (Settings & Shortcuts)

| 항목 | 내용 |
|------|------|
| **F8-1. 글로벌 단축키** | 주요 기능(번역 시작/중지, 모드 전환, 표시 전환, 영역 재지정)에 글로벌 단축키를 할당할 수 있다. 다른 프로그램 위에서도 동작한다. |
| **F8-2. 설정 UI** | 트레이 아이콘을 통해 접근하는 설정 창에서 모든 설정 항목을 관리한다. |
| **F8-3. 설정 저장** | 모든 설정은 로컬 파일(JSON 또는 TOML)에 저장되며, 프로그램 재시작 시 자동으로 불러온다. |

## 7. 비기능 요구사항 (Non-Functional Requirements)

### 7.1 성능

- 캡처 → 표시까지의 전체 파이프라인 지연 목표 (짧은 문장 1~2줄 기준):
  - 경량 클라우드 모델 (Gemini Flash Lite 등): 평균 5초 이내
  - 일반 클라우드 모델 (GPT-4o-mini, Claude Haiku 등): 평균 7초 이내
  - 로컬 모델 (20~30 tps 기준): 평균 5~8초
- LLM 이외 구간(캡처 + 변경 감지 + OCR + 캐시 조회)의 총 지연은 1초 이내를 목표로 한다.
- 변경 감지에서 "변경 없음"으로 판단하는 경우, 50ms 이내에 스킵이 완료되어야 한다.
- 캐시 히트 시 100ms 이내에 번역 결과를 표시한다.
- 프로그램 자체의 메모리 사용량은 300MB 이하를 유지한다.
- 참고: LLM 응답 지연은 모델, 네트워크, 입력 길이에 따라 크게 변동하며, 위 수치는 최적화 목표이지 보장 수치가 아니다.

### 7.2 사용성

- 처음 사용하는 사람이 5분 이내에 기본 번역 기능을 사용할 수 있어야 한다.
- 설정 UI는 한국어를 기본으로 제공한다.

### 7.3 확장성

- LLM 프로바이더 추가 시 기존 코드 수정 없이 어댑터만 추가하면 되는 구조로 설계한다.
- OCR 엔진 교체/추가가 인터페이스 수준에서 가능하도록 한다.

### 7.4 안정성

- OCR 실패, API 타임아웃, 네트워크 오류 등 예외 상황에서 프로그램이 크래시하지 않고 사용자에게 상태를 알린다.
- 비정상 종료 시 마지막 설정 상태를 자동 복구한다.

## 10. 리스크 및 완화 방안 (Risks & Mitigations)

| 리스크 | 영향도 | 완화 방안 |
|--------|--------|-----------|
| **LLM API 응답 지연** | 높음 | 캐시 시스템으로 반복 호출 억제, 변경 감지로 불필요한 호출 제거, 로컬 모델 옵션 제공 |
| **OCR 인식률 한계** | 중간 | 이미지 전처리로 인식률 개선, LLM 교정으로 오류 보완, Vision API 모드로 OCR 단계 자체를 우회 가능, 향후 대안 OCR 엔진 교체 가능한 구조 |
| **API 비용 누적** | 중간 | BYOK 방식으로 비용을 사용자에게 투명하게 전가, 캐시/변경 감지로 호출 최소화, 로컬 모델 옵션 |
| **전체 화면 게임 위 오버레이 호환성** | 중간 | PyQt6의 WindowStaysOnTopHint + 투명 배경 조합으로 대응, 호환되지 않는 경우 사이드 패널 모드로 우회 |
| **배포 파일 크기** | 낮음 | Tesseract + Python 런타임 포함 시 200MB+ 예상, Nuitka 등으로 최적화 검토 |

## 부록 A. 용어 정의 (Glossary)

| 용어 | 정의 |
|------|------|
| **OCR** | Optical Character Recognition. 이미지에서 텍스트를 추출하는 기술. |
| **LLM** | Large Language Model. 대규모 언어 모델. GPT, Gemini, Claude 등. |
| **BYOK** | Bring Your Own Key. 사용자가 자신의 API 키를 직접 입력하여 서비스를 이용하는 방식. |
| **오버레이** | 다른 프로그램 위에 투명하게 겹쳐 표시되는 UI 요소. |
| **프리셋** | 사전 저장된 시각적 설정 묶음. 폰트, 색상, 투명도 등의 조합. |
| **번역 프로필** | 번역 대상 콘텐츠의 성격을 정의하는 설정 묶음. 콘텐츠명, 장르, 분위기, 고유 용어집 등을 포함하며, LLM 시스템 프롬프트 생성에 사용된다. 프리셋이 "어떻게 보여줄지"라면, 프로필은 "어떻게 번역할지"를 결정한다. |
| **MORT** | My Overlay Real-time Translation. 기존 Windows용 화면 번역 도구. |
| **Ollama** | 로컬 환경에서 오픈소스 LLM을 구동할 수 있는 도구. API 형태로 모델을 제공한다. |
| **Vision API** | 이미지를 직접 입력받아 분석할 수 있는 LLM 기능. Gemini, GPT-4o 등이 지원하며, OCR 없이 이미지 내 텍스트를 인식하고 번역할 수 있다. |

```
[화면 캡처] → [변경 감지] →(변경 없음)→ SKIP
                  ↓ (변경 있음)
            [번역 경로 선택]
                  │
      ┌───────────┴───────────┐
      ↓ 경로 A (OCR+LLM)      ↓ 경로 B (Vision)
  [OCR 추출]              [이미지를 Vision LLM에 전달]
      ↓                   (인식 + 번역 한 번에)
  [캐시 조회]                  ↓
      ├─(히트)→ [캐시된 번역]   │
      ↓ (미스)                 │
  [LLM 번역 요청]              │
  (OCR 교정+문맥+번역)         │
      └───────────┬───────────┘
                  ↓
          [번역 결과 캐시 저장]
                  ↓
              [화면 표시]
          (오버레이 / 사이드 패널)
```
